# 轨迹记（working name: TrackLog）— 产品设计文档

> 版本：v0.1（立项稿）  日期：2026-10-15
> 文档状态：方向已锁定。本文档是项目主心骨，后续开发以此为准；要改方向先改这份文档。

---

## 1. 一句话定位

一个**纯本地、离线可用、无广告**的 GPS 轨迹记录工具：打开即定位，一键开始记录运动/行车轨迹，实时画线，结束后保存距离、时长等数据到本地，可回看历史。

---

## 2. 背景与目标

**为什么做这个（双重目标）：**

1. **走通 Flutter 全流程**（第一优先级）
   从零搭环境 → 开发 → 构建 → 签名 → 国内上架，把"Flutter 从 0 到上架"这条链路完整走一遍。这是当前最核心的目标。

2. **方向要能演进到赚钱**（第二优先级，不急于变现）
   选"GPS 轨迹"这个底座，是因为它的核心技术（定位采集、轨迹绘制、距离计算、后台保活）**通用可复用**，后续可按市场换外壳变现（见第 9 节）。

**明确不追求的：** v1 不以赚钱为目标。国内个人开发者身份下，纯本地免费工具主要作用是**作品 + 能力证明 + 跑通流程**。

---

## 3. 目标用户与场景

- v1：**自己 + 愿意试用的运动/户外用户**（跑步、骑行、徒步记录轨迹）
- 场景：出门运动，开始记录 → 全程后台采点 → 结束查看这次的路线、距离、时长 → 历史回看

> 注：真正的付费人群在演进阶段才锁定（出海里程报税 / 国内运动或外勤），v1 不纠结人群。

---

## 4. 产品原则（防跑偏的红线）

1. **单一功能做好**：只做"记录轨迹"这一件事，不堆功能
2. **本地优先、离线可用**：无服务端，数据存本地，断网能用
3. **无广告、无强制登录、无付费墙**：契合国内个人号上架要求，也是差异化
4. **真机优先**：定位功能以真机为准（模拟器 GPS 不可靠）

---

## 5. 功能范围与切片规划

**v1（MVP，当前目标）—— 跑通流程**
- 打开 app 显示地图 + 当前位置蓝点
- 开始/停止 记录
- 实时绘制轨迹线
- 停止后计算并保存：总距离、时长、（可选）平均配速
- 历史记录列表 + 单次轨迹详情回看
- 本地存储

**v2（增强）**
- 后台/锁屏持续定位（前台服务保活）
- GPS 漂移点过滤 / 轨迹平滑
- 轨迹导出（图片 / GPX）
- 配速、海拔等更多指标

**v3（演进/变现方向，二选一按市场定）**
- 出海：里程自动识别 + 公务/私人分类 + 报税报表导出
- 国内：运动健身包装 或 外勤/车队里程（B 端）

## 6. v1 详细范围与验收标准（DoD）

**必须完成（Done 的定义）：**

- [ ] 打开 app，首页显示高德地图，并显示当前位置蓝点（定位成功）
- [ ] 有"开始记录"按钮，点击后开始采集位置点
- [ ] 记录过程中，地图上实时把轨迹点连成线
- [ ] "停止记录"后，计算本次总距离（米/公里）和时长
- [ ] 本次轨迹 + 距离 + 时长 + 时间 保存到本地（SQLite）
- [ ] 历史列表能看到每次记录；点进去能看到那次的轨迹和数据
- [ ] 定位权限申请流程正常（首次使用请求定位权限）
- [ ] 真机上实测走一圈，轨迹和距离基本合理

**v1 明确不做（放到 v2+）：**
- 后台/锁屏持续定位（v1 先只保证前台记录能用）
- 轨迹漂移过滤、平滑算法
- 导出、分享
- 账号、云同步、任何联网上报

## 7. 技术架构

```
┌───────────────────────────────────────────┐
│                Flutter (Dart)              │
│  UI 层：地图页 / 记录页 / 历史列表 / 详情页   │
│  逻辑层：定位采集、轨迹管理、距离计算（Dart） │ ← 核心价值在这，插件吃不掉
│  数据层：本地存储（sqflite / SQLite）         │
└───────────────────────────────────────────┘
        │                         │
   amap_flutter_location     amap_flutter_map
   （高德定位插件）            （高德地图插件）
        │                         │
   Android 原生定位/地图（高德 SDK，国内必须用高德/百度）
```

**技术选型：**
- 框架：**Flutter**（一套代码，后续可出 Android + iOS）
- 地图/定位：**高德**（`amap_flutter_map` + `amap_flutter_location`，国内地图合规必须用高德/百度）
- 本地存储：**sqflite**（SQLite）
- 坐标系：高德返回 **GCJ-02**，与高德地图一致，v1 不涉及跨源坐标转换
- 距离计算：优先用高德 `AMapUtils`（按经纬度球面算，准）

**环境：**
- Android Studio（自带 Android SDK + 模拟器 + JDK17）
- Flutter SDK（PATH 配好，`flutter doctor` 无红叉）
- 高德开放平台 key（绑定项目包名 + SHA1）
- 真机（测 GPS）

- ❌ 不做多端同时上架（先 Android，先国内）
- ❌ 不做地图之外的花哨功能

## 9. 演进与变现路线

```
v1 国内免费作品（走流程 + 能力证明）
        │  同一套 GPS/轨迹/距离核心
        ├──→ 出海：里程报税追踪（自雇/司机，一次性或订阅，$$$）
        └──→ 国内：运动健身轨迹（toC）或 外勤/车队里程（toB）
```

- **核心复用**：定位采集、轨迹、距离、后台保活这套底子通用
- **变现换皮**：出海做"里程报税"（西方有个人里程抵税制度，国内没有）；国内做运动或 B 端外勤
- **前提**：真要变现，出海走 Google Play（个人可一次性付费），国内要变现需注册企业主体 + 广告

## 10. 上架计划（国内个人号）

- 身份：个人开发者账号（纯本地、无联网上报、无广告、无付费 → 符合个人号条件）
- 必备：**软件著作权**（华为/小米/OPPO/vivo 强制，办理约 60-90 工作日，可加急 1-3 天）
- 备案：工信部 APP 备案（填软著编号）
- 隐私政策：需提供隐私政策页面（定位权限说明）
- 先上一个国内商店跑通流程，其余后续

> 注：地图瓦片需联网，严格意义上非"纯单机"；上架时按"工具类"申报，隐私政策说明定位与网络用途。

## 12. 主要风险与应对

- **后台/锁屏定位被杀**（Android 顽疾）：v1 先只保证前台记录；v2 用前台服务 + `foregroundServiceType=location` 保活
- **GPS 漂移/跳点**：v1 不处理；v2 加精度/速度阈值过滤
- **定位权限（Android 10+ 后台定位权限）**：v1 只用前台定位权限，降低复杂度
- **高德 key 配置**（包名 + SHA1 不匹配会定位/地图失败）：建工程后统一申请、仔细核对
- **范围蔓延**（最大风险）：严格按本文档 v1 范围做，想加功能先更新文档

---

## 13. 术语

- **轨迹点**：一次定位得到的经纬度 + 时间（+ 精度/速度）
- **GCJ-02**：中国加密坐标系（火星坐标），高德使用
- **前台服务**：Android 常驻通知的服务，用于后台保活（v2）
- **MVP**：最小可行产品，即 v1
